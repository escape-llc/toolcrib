# Toolcrib

Hi! Welcome to Toolcrib, an AI-generated UI toolkit, targeted at AI model consumption.

> This file is the only human-created content in the whole repo!  The rest was generated by AI, using various IDEs and AI models.

## Rationale

Vibe coding UI is terribly painful.  Getting an initial result, but then "tweaking" is a horrible affair of wasted turns adjusting padding, margins, etc.  Unfortunately, models do not carry this out consistently, so there are extra turns/expense involved.

Even things as simple as "add a button" is not trivial. Do you want:
- a ghost button?
- A solid button?
- Round corners?
- Rounded edges?
- A label?
- ALL CAPS?! 
- The "primary" color? 
- The "danger" color? 
- Is there a "danger" color even defined app-wide?

It gets worse! Each time you ask for the "same" UI element, like a Toolbar, the model simply regenerates it anew. And it may use the same or similar styling it used last time.  The same applies to popups, modals, forms, etc.  So consistency is not likely.

After experiencing this "herding the cats" personally, I asked numerous different AI models about "whether a specially-designed toolkit optimized for AI model consumption" would be a good idea.  They all said yes!  So here it is!

## Philosophy

Following the Rodney Dangerfield joke of "I told my doctor: It hurts when I do that.  He said: Don't do that".

Left to its own devices, the model works out a "jumble" of tailwind-inspired ad hoc styling.  And it does this anew with each turn.  And it looks great--at first blush.  But then you start tweaking, and it falls apart.  The problem is that the model does not have "memory" of the styles it has already generated.  There is no real "cohesion" to the output.

Toolcrib fixes this by removing the model's ability to generate `class` or `style` attributes.  Instead, the model is forced to use the components provided.  This gives the model a solid foundation to build on.  If the model wants a "button", it uses the `<Button />` component.  This Button component already knows how to be a primary button, a success button, etc.  The model does not have to constantly re-specify that, for example.  There is a single source of truth.

# Installation

> Install before you get started vibe coding!

The deployment model for Toolcrib is "Full Vendoring" meaning you copy all the source into your repo.  This is also how `shadcn` operates.  This gives the model complete access to how the toolkit works, and allows the model to alter the toolkit for your specific needs.

> Refer to the USER_GUIDE.md file for detailed instructions!

# Usage

To get the most out of Toolcrib, you need to tell your AI agent to use it.

There are assets in the `ai-docs` folder you can integrate into your `AGENTS.md` or other similar files.

The `component-manifest.json` is a machine-readable manifest of the toolkit API surface. Refer to this file, instead of piling API descriptions into your prompts.

> The CLI will install these for you (as patches)!

# Theming

The goal of this toolkit is to take styling away from the AI, and give it to you (or the user).

The toolkit comes with OOTB Theme Editor; use it or don't!

Once you have "presets" nailed down, you can integrate them directly into your app during init.
