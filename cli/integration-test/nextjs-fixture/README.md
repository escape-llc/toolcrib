# Next.js App Router fixture

A minimal, pre-`toolcrib apply` Next.js App Router skeleton — the target
for `../run-nextjs-fixture.mjs`, which is the actual thing to run (see its
own header comment, and `cli/CONTRIBUTING.md`'s integration-test section).

## What's committed here vs. generated at run time

Committed: `package.json` (plain Next.js/React/TypeScript deps only — no
toolcrib wiring yet), `next.config.ts`, `tsconfig.json`, `app/layout.tsx`
(implements `ai-docs/examples/ssr-theme-injection.md`'s documented SSR
theme-injection pattern), `app/providers.tsx` (the client half of that
pattern, wrapping `<ToolcribProvider>`).

Generated by `run-nextjs-fixture.mjs` into a *copy* of this directory,
never here: `toolcrib/` and the `#toolcrib` entry in `package.json`'s
`imports` field (both added by the real `toolcrib init`/`apply`, run
against a local mock GitHub server — see `../mock-github-server.js`),
`node_modules`, `.next`, `next-env.d.ts`, and every `demo/*.ts` / `demo/*.tsx` / `demo/*.json` file
(into `app/`, with `demo/App.tsx` becoming `app/DemoApp.tsx`; only the
Vite-only files in the script's `EXCLUDED_DEMO_FILES` are skipped, and a
guard fails the run if a copied file imports something that isn't there),
plus `app/demo.css` / `public/toolcrib-256x256.png` / `app/page.tsx`
(from `demo/index.css` / `demo/toolcrib-256x256.png` — the originals are
untouched).
Two things are rewritten in the copy only: `'use client'` is prepended to
each source file (the originals aren't vendored source, but still need the
directive to be usable as Client Components here), and the icon import is rewritten from
a relative asset import to a `public/`-served URL string, since Vite's
PNG import yields a `string` but Next.js's yields a `StaticImageData`
object — a real Vite/Next.js static-asset difference the script's own
comment explains in full.

## Why reuse `demo/App.tsx` instead of writing separate fixture content

The `'use client'` boundary bug this fixture exists to catch is per-file
(the directive is present or it isn't), and importing *anything* through
the `#toolcrib` barrel pulls Next's RSC-boundary analysis across the
entire re-exported graph — confirmed for real while finding the original
51-vs-79-file gap (see `AGENTS.md`'s `'use client'` section). A small,
dedicated fixture component would exercise the exact same whole-graph
check as reusing the real demo, so reusing `demo/App.tsx` gets the same
coverage as a hand-written one would, plus the actual component surface
the Vite demo exercises, without a second demo body to keep in sync on
every future component addition.
